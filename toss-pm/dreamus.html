꿈 이야기를 AI 이미지와
VR 공간으로 만드는 대화형 서비스

꿈 이야기를 이미지 생성 조건으로 바꾸는 대화 흐름을 기획하고, 개발팀과 프롬프트 구조를 조율했습니다. 생성 거부가 잦던 모델을 바꾸고, 생성 대기 중의 경험을 설계했습니다.

제안·선정부터 완료까지 PM. 대화 시나리오와 UI/UX를 기획하고, 프롬프트 방향과 팀별 구현 범위를 조율

3단계 프롬프트 구조, 생성 거부 대응을 위한 DALL·E→Flux 전환, 입력·요약 이중 검사, 대기 중 대화·명상 배치

생성 요청에서 빠지는 사용자 의도와 길고 불규칙한 대기

단편적인 꿈 이야기만으로는 사용자가 떠올린 장면과 감정을 생성 결과에 담기 어려웠습니다. 생성 요청이 거부되거나 재시도가 길어지는 문제도 있어, 대화와 생성 대기를 하나의 경험으로 다뤘습니다.

대화를 생성 조건으로 바꾸는 3단계 프롬프트

배경·사건·키워드에서 출발해 이미지의 세부 묘사와 감정, 연결되는 삶의 경험을 묻는 대화 흐름을 기획했습니다. 이 대화를 생성 요청으로 바로 넘기지 않도록, 개발자와 함께 정보 추출·요약·형식 변환의 세 단계로 나누고 단계마다 무엇을 출력해야 하는지 조율했습니다.

01정보 추출

장면·감정·개인 맥락을 묻고, 필요한 정보를 다 얻었는지 판단

02정보 요약

대화 내용을 장면·감정·인상으로 정리 (한국어·영어)

03형식 변환

정리한 내용을 생성 모델용 프롬프트 한 개로 변환

01 정보 추출 프롬프트의 출력
{
  "response": "사용자에게 건네는 다음 질문",
  "is_end": "필요한 정보를 다 얻어 대화를 끝내도 되는지"
}
02 정보 요약 프롬프트의 출력
{
  "dream_information_korean": {
    "characters": "꿈속 장면·배경·사물",
    "feeling": "꿈을 꾸는 동안의 감정",
    "impression": "꿈에 대한 전체 인상"
  },
  "dream_information_english": { … }
}

출처: 개발팀 엔지니어링 위키(2024.10)의 출력 형식 요약. 프롬프트 구현은 개발자가 맡았고, 저는 단계마다 받아야 할 정보와 대화를 끝낼 시점(is_end)을 개발자와 조율했습니다.

모델을 바꾼 이유와 대체 모델을 고른 이유

기존 모델을 바꾼 이유

초기에는 DALL·E로 이미지를 생성했지만, 꿈 이야기에서 나온 요청이 콘텐츠 정책에 따라 반복적으로 거부됐습니다. 문제가 될 수 있는 단어를 빼거나 같은 프롬프트로 다시 호출해 대응했지만, 재시도가 쌓이면서 생성 시간이 길어졌습니다. 그래서 대체 모델을 검토했습니다.

대체 모델을 고른 이유

후보인 Flux와 SDXL의 결과를 같은 프롬프트로 비교했습니다. 이미지 품질과 요청 요소의 반영뿐 아니라, 360도 VR에서 낯선 장면이 주는 두려움을 고려해 친근한 표현을 기준에 포함했고, 요청 요소와 원하는 표현 스타일을 반영한 Flux를 선택했습니다.

당시 팀의 모델 비교 기록에서 발췌한 결과입니다. 제시한 비교 사례에서는 Flux가 인물·곰처럼 프롬프트에 적힌 요소와 3D 애니메이션 스타일을 반영했고, SDXL은 일부 요소가 빠지거나 실사에 가까운 이미지가 나왔습니다. 모델 전체의 성능 비교는 아닙니다.

최종 결정

팀의 생성 모델을 DALL·E에서 Flux로 전환했습니다.

운영 제약에 맞춰 조정한 제품 동작

제약판단반영한 동작
길고 불규칙한 생성 시간대기 중 이탈 가능성 고려감정 대화와 명상 배치
전시되는 꿈의 누적서버 운영·실행 부담 고려꿈 5개 무작위 표시와 셔플 탐색
정책에 저촉되는 표현생성 이전에 입력·요약을 검사문제 표현을 자동 순화하는 처리 적용

대화 입력과 생성 요약 단계에 OpenAI Moderation API 검사를 적용하고, 감지된 표현은 순화해 생성하도록 개발팀과 정했습니다. 콘텐츠 정책에는 폭력·선정성뿐 아니라 실존 인물과 저작권 캐릭터 요청도 검토 대상으로 두었습니다.

이중 검사와 순화는 당시 적용한 대응이며, 모든 정책 범주에 대한 탐지 성능은 별도로 검증하지 않았습니다.

꿈 작업장은 만들기와 확인, 꿈 전시장은 탐색과 공유에 초점을 맞췄습니다. 두 공간을 연결해 개인의 생성 경험이 다른 사람의 참여로 이어지도록 설계했습니다.

대화 시나리오 설명

꿈 작업장의 대화는 배경과 장면을 떠올리는 단계에서 시작해 주요 이미지와 감정을 구체화하고, 자신의 삶과 연결하는 흐름으로 구성했습니다. 전체 시나리오를 대화 스크립트로 풀어내고, 프롬프트 실험과 UI/UX 설계에 연결했습니다.

생성 이후에도 사용자가 결정하는 분기 두기

승인·재생성 흐름 설명

대화에서 정리한 내용을 바탕으로 세계를 생성한 뒤, 사용자가 자신의 꿈과 비슷한지 확인하는 단계를 설계했습니다. 승인하면 꿈 세계를 완성하고, 재생성을 선택하면 설명을 바꿔 다시 대화하는 흐름입니다. AI의 출력 이후에 사용자의 확인과 다음 행동이 이어지도록 구성했습니다.

작업장·전시장 구현 범위

만드는 흐름과 감상하는 흐름을 구분하기

꿈 작업장은 대화·시각화·확인과 수정·세계 생성, 꿈 전시장은 탐색·공간 진입·감정 반응·다음 꿈으로 이어집니다. 전시장에서는 입장할 때 제시되는 다섯 꿈을 탐색하고 선택한 공간을 경험하도록 구성했습니다. 개인 보관함과 지속적 공유는 후속 구상으로 남겨, 구현한 전시 경험과 구분했습니다.
